# Lessons

**Rule:** learning is complete only when it changes future behaviour.

## Run

1. State what actually happened and what assumption changed.
2. Extract one reusable rule in plain language.
3. Find the smallest existing owner that should change: root router, `structure`, `skill-builder`, `auditor`, a domain Skill or another local Skill.
4. Implement the correction immediately when authorised and small enough.
5. Prove the original failure is harder to repeat or the successful pattern easier to reproduce.
6. Preserve lesson provenance only when it adds future value. Create `.folderdesk/lessons/LESSONS.md` on the first genuinely useful retained lesson, not before.

## Compact retained shape

```text
### <short lesson>
Observed: <what happened>
Changed assumption: <if material>
Rule: <reusable rule>
Implemented: <owner/path/change>
Proof: <representative check>
```

## Boundaries

- Not an incident system, diary, changelog, backlog, scorecard or approval gate.
- Do not capture ordinary progress, status, trivia or every mistake.
- Do not preserve a lesson instead of implementing its obvious correction.
- When a lesson becomes a stable foundational invariant, promote it into its canonical Skill and keep only useful provenance.

**Acceptance:** a material lesson changes the smallest canonical owner, is proved once, and leaves no new ceremony behind.
